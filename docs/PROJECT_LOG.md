## 2. 단계별 진행 기록

| 단계 | 결과 |
|---|---|
| ① 문제 발견 | "파이썬 개념은 이해했지만, 문제를 보면 **어떤 순서로 풀지**, **각 단계에 어떤 문법을 써야 할지** 떠오르지 않아 코드를 시작하지 못한다." |
| ② 사용자 정의 | 컴공 1학년 · **수업 직후 복습** · **노트북과 폰 둘 다** · 정답보다 스스로 푸는 힘이 필요 |
| ③ 기능 결정 | 1번 연습 문제 + 3번 문법 힌트 + 6번 개념 필터, 그리고 **푼 문제 복습·성장 과정** |
| ④ 화면 설계 | 따로 하지 않고 바로 제작 (발표 전에 기획서로 거꾸로 정리) |
| ⑤ 기획서(PRD) | 아래 3장 |
| ⑥ 제작 | 1차 버전 → 8차 버전까지 (4장) |
| ⑦ 테스트·개선 | 직접 써 보며 버그 발견, 제약을 만나면 다른 방법 찾기 (5장) |
| ⑧ 발표·성찰 | 슬라이드 7장 + 발표문 + 예상 질문 정리 |

### 처음에 고른 방향 (②~③ 사이)

막히는 지점이 세 군데였어요.

| 유형 | 막히는 순간 |
|---|---|
| A. 시작 | 문제를 읽고 빈 화면 앞에서 멍해짐 |
| B. 연결 | for, if, 리스트를 언제 써야 할지 모름 |
| C. 마무리 | 에러가 나면 어디서 틀렸는지 모름 |

→ **2안(A + B 묶기)**을 선택했어요. 문제를 단계로 쪼개고, 단계마다 문법 힌트를 주는 방식이에요. C(에러 해결)는 다음 버전으로 미뤘다가, 2차 버전에서 "에러 읽는 법"으로 맛보기를 넣었어요.

## 5. 부딪힌 문제와 해결

| 부딪힌 문제 | 어떻게 알았나 | 해결 방법 |
|---|---|---|
| AI가 만든 문제의 정답이 틀릴 수 있음 | AI의 한계를 미리 고려 | 정답 코드를 앱이 직접 실행해서 에러면 버리고, 출력이 다르면 실제 결과로 고치고 ⚠️ 표시 |
| 다크 모드에서 드롭다운 글자가 안 보임 | **직접 써 보다가 발견** | 글자색·배경색을 직접 지정, 앱은 밝은 화면으로 고정 |
| 폰에서 앱이 안 열림 | 직접 폰으로 열어 봄 | 앱이 비공개 상태 → 같은 계정 로그인 / 공유 설정 |
| 앱 안에서는 카메라·마이크를 쓸 수 없음 | 화상회의 기능을 만들려다 확인 | 말랑이 아바타 회의실 + 얼굴 인식 아바타 카메라를 별도 파일로 |
| 원작 캐릭터 모델을 쓰고 싶었음 | 3D 모델 파일 정보 확인 | 모델 파일 라이선스와 별개로 **캐릭터 저작권**이 있음 → 오리지널 마스코트 말랑이 |
| 아바타 카메라를 매번 파일로 열기 귀찮음 | 실제 사용 흐름을 생각 | GitHub Pages로 배포 → 앱에서 버튼 한 번 |
| 다른 사람 채팅이 오면 쓰던 글이 지워질 수 있음 | 테스트 중 발견 | 화면을 다시 그려도 입력 중인 칸은 유지 |
| 폰에서 말랑이가 화면 밖으로 삐져나옴 | 모바일 화면 확인 | 세로 화면에서는 카메라를 뒤로 물리고 찌그러짐을 줄임 |

## 6. AI 활용 기록

| 내가 한 일 | AI(Claude)가 한 일 |
|---|---|
| 문제 정의 (내 경험에서 출발) | 문제를 A·B·C로 쪼개는 질문과 선택지 제안 |
| 기능 고르기 (1·3·6번 + 복습·성장) | 기능 후보와 장단점 정리 |
| 방향 결정 (AI 문제 B안, 아바타 C안 등) | 선택지별 장단점과 추천 |
| 직접 써 보며 버그 찾기 (다크 모드, 모바일) | 원인 설명과 수정 |
| 친구·회의 등 새 기능 아이디어 | 가능/불가능 확인 후 대안 제시, 코드 작성 |
| 저작권 문제 확인 후 오리지널 캐릭터로 결정 | 저작권과 라이선스 차이 설명 |
| GitHub 저장소 만들기, 권한·Pages 설정 | 파일 정리, 커밋, 업로드 |

**배운 점**: AI는 대신 만들어 주는 도구가 아니라 **같이 고민하는 러닝메이트**였다. 질문을 구체적으로 할수록 결과가 좋아졌고, AI가 틀릴 수 있다는 걸 알고 **직접 실행해서 확인하는 습관**이 생겼다.
